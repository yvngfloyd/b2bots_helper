# B2Bots Helper

Telegram-бот для приёма заявок от потенциальных клиентов.

## Что умеет

- Показывает стартовый экран с кнопками.
- Даёт кнопки на сайт и Telegram-канал.
- Просит подписаться на Telegram-канал перед стартом или продолжением анкеты.
- Запускает анкету для квалификации лида.
- Собирает ответы пользователя.
- Отправляет владельцу готовую заявку в Telegram.
- Отправляет владельцу уведомление о каждом пользователе, который нажал `/start`.
- Напоминает пользователю завершить заявку картинками: первый раз через час, затем раз в несколько дней.
- Поддерживает обложку через `COVER_FILE_ID`.

## Быстрый запуск

1. Создай `.env` на основе `.env.example`.
2. Установи зависимости:

```bash
pip install -r requirements.txt
```

3. Запусти бота:

```bash
python main.py
```

## Что обязательно заполнить в `.env`

- `BOT_TOKEN` - токен бота от BotFather.
- `OWNER_CHAT_ID` - твой Telegram ID, куда будут приходить заявки.
- `SITE_URL` - ссылка на сайт.
- `TG_CHANNEL_URL` - ссылка на Telegram-канал.
- `REQUIRE_SUBSCRIPTION` - включает обязательную подписку перед анкетой. Сейчас по умолчанию `false`; чтобы вернуть проверку, поставь `true`.
- `SUBSCRIPTION_CHANNEL_ID` - канал для проверки подписки. Для публичного канала можно указать `@username` или ссылку `https://t.me/...`; для приватного канала нужен числовой id вида `-100...`. Если не заполнить, бот попробует взять `@username` из `TG_CHANNEL_URL`.
- `BOT_TITLE` - название бота.
- `COVER_FILE_ID` - необязательно. Когда будет обложка, просто вставь file_id.
- `DATABASE_PATH` - путь к SQLite-базе для пользователей и напоминаний. Локально по умолчанию `bot_data.sqlite3`. На Railway лучше оставить пустым и подключить Volume: бот сам возьмёт `RAILWAY_VOLUME_MOUNT_PATH/bot_data.sqlite3`.
- `FIRST_REMINDER_HOURS` - через сколько часов отправлять первое напоминание. По умолчанию `1`.
- `REMINDER_REPEAT_DAYS` - как часто повторять лёгкие напоминания. По умолчанию `3`.
- `REMINDER_CHECK_SECONDS` - как часто бот проверяет, кому пора отправить напоминание. По умолчанию `300`.
- `ADMIN_TOKEN` - необязательный bearer-токен для защищённого доступа к CRM API. Если используешь публичную CRM на Railway, проще и удобнее также заполнить `CRM_USERNAME` и `CRM_PASSWORD`, чтобы браузер мог открыть страницу через Basic Auth.

## Как узнать свой chat_id

Самый простой способ:

- написать любому боту для определения ID;
- либо временно добавить логирование update и посмотреть свой user id.

## Команды

- `/start` - открыть главное меню.
- `/menu` - открыть главное меню.
- `/cancel` - отменить текущую заявку.

## Локальная CRM

Мини-CRM показывает пользователей из SQLite-базы: статус заявки, даты, username, последний шаг, последнее сообщение, источник, счётчик напоминаний, ответы анкеты и заметки. Бот сохраняет или обновляет пользователя на `/start`, на каждом сообщении и на каждом нажатии кнопки. Новые завершённые заявки сохраняют финальные ответы отдельно от черновика, поэтому они остаются видны в CRM после завершения.

Локальный запуск:

```bash
python crm_server.py
```

Открой:

```text
http://127.0.0.1:8080
```

Если база лежит в другом месте:

```bash
DATABASE_PATH=/path/to/bot_data.sqlite3 python crm_server.py
```

Если бот работает на Railway, локальная CRM на ноутбуке не увидит пользователей из Railway-базы. Чтобы CRM читала ту же базу, что и бот, включи её внутри процесса бота:

```text
CRM_ENABLED=true
CRM_HOST=0.0.0.0
CRM_USERNAME=admin
CRM_PASSWORD=strong-password
```

На Railway порт берётся из переменной `PORT` автоматически. `CRM_USERNAME` и `CRM_PASSWORD` лучше заполнить обязательно, потому что CRM будет доступна по публичному URL сервиса.

Страница CRM сама опрашивает API каждые 7 секунд, поэтому новые пользователи появляются без ручного обновления. Доступные endpoints:

```text
GET /api/users
GET /api/users/{telegram_id}
PATCH /api/users/{telegram_id}
GET /api/users/stats
GET /api/users/export.csv
GET /api/users/export.tsv
GET /api/users/export.xlsx
```

`PATCH /api/users/{telegram_id}` принимает `application_status`, `notes` и `is_blocked`. Если задан `ADMIN_TOKEN`, API принимает заголовок `Authorization: Bearer <ADMIN_TOKEN>`. Для обычного открытия страницы в браузере на Railway оставь включёнными `CRM_USERNAME` и `CRM_PASSWORD`.

Чтобы база не терялась и точно была подключена к Railway-боту:

1. Создай Volume в Railway и подключи его к сервису бота.
2. Mount path поставь, например, `/data`.
3. Удали переменную `DATABASE_PATH` или оставь её пустой. Если она равна `bot_data.sqlite3`, бот тоже автоматически перенесёт файл в Volume.
4. После редеплоя в `/debug` должно быть видно `Database path: /data/bot_data.sqlite3`.

Если хочешь задать путь руками, поставь:

```text
DATABASE_PATH=/data/bot_data.sqlite3
```

Главное: Start Command сервиса должен быть `python main.py`. В репозитории есть `railway.json`, который задаёт это автоматически для новых деплоев.

Если CRM открывается, но таблица пустая после `/start`, открой `/debug` на том же домене. Там будет путь к SQLite-файлу, размер базы, количество строк и последние пользователи. В Railway Logs после каждого `/start` также должна появиться строка `Saved /start user_id=... database_path=... users_count=...`. Если этой строки нет, `/start` обрабатывает другой запущенный экземпляр бота.

## Деплой

Подходит для Railway, Render, VPS и других обычных Python-окружений.

Для Railway можно запускать командой:

```bash
python main.py
```

Важно: чтобы проверка подписки работала стабильно, добавь бота в канал и дай ему права администратора. Telegram должен разрешать боту вызывать `getChatMember` для этого канала. Если Telegram не даст проверить подписку, бот отправит владельцу точную ошибку и канал, который он пытался проверить. Если пользователь нажмёт «Проверить подписку», но Telegram вернёт статус `left` или `kicked`, владелец тоже получит диагностическое сообщение с проверяемым каналом.
